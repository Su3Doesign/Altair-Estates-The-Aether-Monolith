# Release scope

## Product edition

The source baseline is the owner's `car-mansion` commit `a3fe35edd4e8c49d416613f0cc8f7a1fd720f243`. The private production copy uses an explicit procedural-module allowlist with a hash manifest; it does not copy source binary assets or portfolio renders.

| Group | Treatment |
| --- | --- |
| Procedural tree geometry, bark and leaves | Retained; three seeded variants per species and a controllable crown-sway demonstration added |
| Cedar gatehouse | Extracted to local metric coordinates; separate hinged leaves, useful opening control and practical lighting added |
| Glass pavilion | Developed as a standalone structure using project procedural finishes; stairs, handrails, glow and lighting controls added |
| Courtyard arch | New independent bay developed from the estate's architectural vocabulary; separate stone units and hinged slatted gates |
| Mansion and estate architecture | Migrated to an original-material engineering edition; native scene generation verified separately from commercial visual acceptance |
| Scanned materials | Fetch code replaced with project-authored procedural material paths; no network texture requests |
| Downloaded plants and decorative props | Omitted; scanned potted plant species mapped to the project's generated tropical plants |
| Third-party painting | Replaced with the project's generated sky artwork |
| Vehicle models, logos, liveries and automotive accessory kit | Excluded from production packages |
| Designer-chair replica | Excluded pending a broader design/reference review |
| Original rugs, procedural sky and shoreline distance map | Generated from source, packed in the large scenes |

Procedural generation is evidence about the source process, not a legal certification that every referenced design is unencumbered. Keep design records and complete the seller's rights review before publication. Accurate authorship credit and any required marketplace tool disclosures remain separate from whether code has a recognizable style.

## What is supplied

The standalone Blender products have named PRODUCT and PRESENTATION_INCLUDED collections, metre units, native node materials, cameras, a start guide, manifest and fresh-process QA report. Gate controls open both leaves; tree controls vary a 240-frame crown-sway loop. These motions are animation examples, not physics simulations. Material nodes are Blender-native; cross-engine fidelity is not promised.

The private archives contain only explicitly selected delivery files and per-file checksums. They do not include the production source, old Git history, downloaded cars, scanned props or external dependencies. They remain owner-review archives until a storefront licence is selected.

## Remaining release gates

1. Approve the final native previews and inspect each asset from all sides, including close-up material/detail quality.
2. Repeat import/appending checks after any asset changes; all nine standalone products passed appending into an empty scene with their specified controls. Measure representative scene memory/performance on the intended hardware.
3. Verify current marketplace acceptance, seller country/payout eligibility, required declarations and applicable licence terms.
4. Confirm product-specific listings accurately describe variants, animation, native format and limitations.
5. Activate checkout only after secure private delivery and support details are configured.

The mansion and estate require additional room-by-room review, material tuning, presentation lighting and scene optimization. Passing a build and dependency check is not a substitute for that review.
